# غِراس 🌱

**قصصٌ تُروى، وقيمٌ تُغرس**

أداة ويب بسيطة تولّد قصة أطفال عربية مخصصة بأسلوب إسلامي، مع صورة واحدة لأهم مشهد في القصة.

**🌐 الموقع المباشر:** [ghiras.kids](https://ghiras.kids)

## التقنيات

- Next.js (App Router) + TypeScript
- Tailwind CSS
- OpenAI لتوليد النص والصورة
- Zod للتحقق من المدخلات والمخرجات
- خط «ثمانية» محليًا عبر `next/font/local`

بدون تسجيل دخول. مولّد القصة المجاني لا يحفظ شيئًا، ولا يُحفظ إلّا طلبٌ مدفوع
(بياناته وقصته) ليُسلَّم آليًا، ويُحذف تلقائيًا بعد مدّة قصيرة — التفاصيل في
[التسليم الآلي](#التسليم-الآلي).

## التشغيل

1. ثبّت الحزم:

   ```bash
   npm install
   ```

2. انسخ ملف البيئة وأضف مفتاح OpenAI:

   ```bash
   cp .env.example .env.local
   # ثم ضع مفتاحك في OPENAI_API_KEY
   ```

3. شغّل الخادم:

   ```bash
   npm run dev
   ```

4. افتح المتصفح على [http://localhost:3000](http://localhost:3000)

## متغيرات البيئة

| المتغير | الوصف |
| --- | --- |
| `OPENAI_API_KEY` | مفتاح OpenAI (مطلوب) |
| `OPENAI_TEXT_MODEL` | نموذج النص (اختياري، الافتراضي `gpt-4o-mini`) |
| `OPENAI_IMAGE_MODEL` | نموذج الصورة (اختياري، الافتراضي `gpt-image-1`) |
| `MOYASAR_SECRET_KEY` | المفتاح السري لبوابة الدفع «ميسر» (اختياري — بدونه يظهر الدفع كـ«قريبًا») |
| `MOYASAR_WEBHOOK_SECRET` | الرمز السري للتحقق من إشعارات ميسر |
| `NEXT_PUBLIC_SITE_URL` | عنوان الموقع لبناء رابط العودة بعد الدفع (اختياري) |
| `RESEND_API_KEY` | مفتاح Resend لإرسال الخدمة على بريد المشتري (اختياري) |
| `EMAIL_FROM` | المُرسِل على نطاق موثّق في Resend (اختياري) |

## الدفع الإلكتروني (ميسر)

الخدمات المدفوعة في `/khadamat` تُدفع عبر [ميسر](https://moyasar.com) بطريقة
Invoices API: يُنشئ الخادم فاتورة ثم يُحوّل المشتري إلى صفحة دفع مستضافة عند
ميسر، فلا تمرّ بيانات البطاقة على غِراس إطلاقًا.

**المسارات:**

| المسار | الوظيفة |
| --- | --- |
| `POST /api/checkout` | إنشاء الفاتورة وإرجاع رابط الدفع |
| `/api/moyasar/callback` | عودة المشتري بعد الدفع (يقبل GET و POST) |
| `POST /api/moyasar/webhook` | إشعار ميسر — المصدر الموثوق لتأكيد الطلب |
| `/checkout/result` | عرض نتيجة الدفع بعد التحقق من الخادم، وبدء التسليم |
| `POST /api/fulfill` | تنفيذ الخدمة المدفوعة وإرجاع الصور |

**التفعيل:**

1. من لوحة ميسر ← «مفاتيح الربط» انسخي المفتاح السري التجريبي `sk_test_...`
   واضبطيه في `MOYASAR_SECRET_KEY`.
2. من لوحة ميسر ← «الإشعارات» أضيفي رابطًا إلى `/api/moyasar/webhook` لحدثَي
   `payment_paid` و `payment_failed`، وضعي الرمز السري في `MOYASAR_WEBHOOK_SECRET`.
3. جرّبي عملية شراء كاملة ببطاقة الاختبار، ثم تحقّقي من ظهورها في اللوحة.
4. بعد نجاح التجربة استبدلي المفتاح بـ `sk_live_...`.

> السعر لا يُرسل من المتصفح أبدًا؛ يُقرأ في الخادم من `PRODUCTS` في
> `lib/services.ts`، ويُعاد التحقق من المبلغ والعملة بعد الدفع قبل تأكيد الطلب.

## التسليم الآلي

الخدمات تُسلَّم فورًا بعد الدفع دون تدخّل يدوي، **وتُرسل على بريد المشتري حتى
لو أغلق المتصفح لحظة الدفع**:

1. عند الضغط على خدمة من صفحة القصة، تُحفظ القصة في `localStorage`
   (`lib/story-store.ts`).
2. `POST /api/checkout` يُنشئ الفاتورة ويحفظ الطلب (القصة + البريد) في
   `lib/order-store.ts` مفتاحه رقم الفاتورة.
3. بعد الدفع يُنجَز التسليم من **مسارين متكافئين**، وكلاهما يمرّ على
   `deliverOrder` في `lib/orders.ts`:
   - **إشعار ميسر** (`/api/moyasar/webhook`) — المسار الموثوق، يعمل من الخادم
     وحده بلا متصفح، ويرسل الصور على البريد.
   - **صفحة النتيجة** (`/checkout/result` → `POST /api/fulfill`) — تعرض الصور
     للمشتري فورًا وهو على الصفحة.

   `claimFulfillment` حجزٌ ذرّي (`SET NX`) يضمن أن أوّل واصل فقط يولّد الصور،
   فلا تُدفع تكلفة التوليد مرتين. ومن يجد الطلب مُسلَّمًا يعرض «أرسلناها على
   بريدك».
4. `lib/fulfillment.ts` يخطّط المشاهد ويرسمها على التوازي:

   | الخدمة | المُسلَّم |
   | --- | --- |
   | `extra-image` | صورة لمشهد آخر يختاره المشتري |
   | `child-likeness` | صورة تحاكي ملامح الطفل كما وصفها أهله |
   | `full-illustrated` | حتى ٥ صور تحكي القصة كصفحات كتاب |

5. الصور تُعرض للتنزيل، وتُرسل على البريد عبر Resend.

### ما يلزم لتفعيل التسليم الآلي

| المتغيّر | بدونه |
| --- | --- |
| `KV_REST_API_URL` + `KV_REST_API_TOKEN` | لا يستطيع الإشعار التسليم؛ يبقى التسليم معتمدًا على بقاء المشتري في المتصفح |
| `RESEND_API_KEY` + `EMAIL_FROM` | لا تُرسل نسخة بريدية، ولا يُوعَد المشتري بها في الموقع |

أنشئي **Vercel KV** (أو Upstash Redis) واربطيها بالمشروع فيُضبط المتغيّران
تلقائيًا. النقص لا يُعطّل الموقع: الدفع والتسليم في المتصفح يعملان، والوعود
المعروضة تتقلّص تلقائيًا لتطابق المتاح فعلًا.

**حفظ البيانات والاحتفاظ:** يُحفظ الطلب المدفوع (بيانات المشتري ونصّ القصة)
لأنّ التسليم الآلي يحتاجه. `RETENTION_DAYS` في `lib/order-store.ts` يحدّد مدّة
الاحتفاظ (١٤ يومًا افتراضيًا) وهي المدّة المعلنة في سياسة الخصوصية — عدّليهما
معًا. ويُحذف الطلب قبلها بمجرّد نجاح الإرسال على البريد. الصور لا تُحفظ على
الخادم إطلاقًا.

**ملاحظات تشغيلية:**

- إن دفع المشتري من متصفح آخر ولم يكن المخزن مُهيَّأً، تطلب صفحة التسليم لصق
  القصة.
- الصور تُحفظ في متصفح المشتري، فتحديث الصفحة لا يُعيد توليدها.
- `lib/fulfillment.ts` يوحّد هيئة الطفل بين الصور عبر `character_sheet`.
- توليد القصة المصوّرة الكاملة قد يتجاوز ٦٠ ثانية؛ `maxDuration` مضبوط على
  ٣٠٠ ثانية وتُقصّره المنصّة حسب الخطة. الرسم متوازٍ ليبقى الزمن قريبًا من
  زمن صورة واحدة.

> ملاحظة: نموذج `gpt-image-1` قد يتطلب توثيق المؤسسة في حساب OpenAI. إن لم يكن متاحًا لديك، اضبط `OPENAI_IMAGE_MODEL=dall-e-3`.
